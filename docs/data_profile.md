Variables with substantial IAP that is **not** ballot-driven (evwork, satjob, indus10, and wwwhr within ballots 1–2) are population filters: the question applies only to a subset (e.g. EVWORK is asked only of respondents not currently working; WWWHR only of internet users). The dbt layer separates these states: `not_asked_ballot` vs `not_applicable`.

**What this means for the questions the pipeline can honestly answer:** questions built on NEWS or TVHOURS (Q4 TV vs job satisfaction, Q6 newspaper/TV trends) can only describe the ~2/3 of each wave on ballots 1-2; INTTECH has the thinnest coverage (~47-53% asked) so technology-interest estimates carry the widest uncertainty; EVWORK-based results (Q5) exclude the unemployed by questionnaire design; everything else (PRAY, RELIG16, POSTLIFE, WRKSTAT, DEGREE, demographics) covers effectively the full sample. Every analysis states its denominator and reports not-asked counts alongside results rather than hiding them.
